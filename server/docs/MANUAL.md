# 勤怠システム(QR打刻 + 残業管理) 操作マニュアル

このマニュアルは、パソコンの専門知識がない方向けです。
**このシステムは、会社の中のWi-Fi(社内LAN)だけで動きます。インターネットには公開されません。**

---

## 0. 全体のイメージ

```
 [打刻用タブレット]   QRコードを表示
        │
 [社員のスマホ] ── 社内Wi-Fi ──→ [サーバーのパソコン]  ← データ(1つのファイル)が入っている
        │
 [管理者のパソコン/スマホ]
```

- **サーバーのパソコン**:社内に1台置きっぱなしにする、Windows 11のパソコンです。電源は常に入れておきます。
- **打刻用タブレット**:QRコードを表示するだけの専用画面です。
- **社員のスマホ**:標準のカメラでQRコードを読み取って、「出勤」「退勤」を押します。

---

## 1. サーバーのパソコンを準備する(最初の1回だけ)

### 1-1. Node.js をインストールする
Node.js は、このシステムを動かすための土台となるソフトです。

1. インターネットにつながるパソコンで https://nodejs.org を開き、**「LTS」(長期サポート版)** をダウンロードします(バージョン22以上)。
2. サーバーのパソコンにコピーして(USBメモリなどで)、ダブルクリックでインストールします。すべて「次へ」で進めて構いません。
3. インストール後、パソコンを再起動します。

> 運用が始まってからは、インターネット接続は不要です。

### 1-2. このパソコンの「住所(IPアドレス)」を固定する
スマホがサーバーを見つけられるよう、住所を変わらないようにします。**この作業は、ルーターの設定画面で行うのが確実です。**

- ルーター(Wi-Fiの親機)の設定画面で、「DHCP固定割り当て」(または「IPアドレス予約」)に、このパソコンを登録します。
- 難しい場合は、ネットワーク担当の方や、ルーターを設置した業者に「このパソコンのIPアドレスを固定したい」と依頼してください。
- 固定した住所(例:`192.168.1.10`)をメモします。調べ方:スタートボタンを右クリック→「ターミナル」→ `ipconfig` と入力して Enter → 「IPv4 アドレス」の数字。

### 1-3. Wi-Fiの設定を確認する
- 会社のWi-Fiは、**パスワード付き(WPA2またはWPA3)** にしてください。パスワードのないWi-Fiでは使わないでください。
- ルーターの「**ゲストWi-Fi**」や「**プライバシーセパレーター(端末間通信の禁止)**」が有効だと、スマホがサーバーに届きません。社員のスマホが使うWi-Fiでは、これらを**オフ**にしてください。
- **ルーターの「ポート開放」(外部公開)の設定は、絶対にしないでください。**

### 1-4. スリープしない設定(重要)
**サーバーのパソコンがスリープすると、サーバーも止まり、タブレットのQRが出なくなります。** 次の設定をしてください(「2_自動起動の登録」でも自動で設定されます)。

- 電源につないだままにします。
- ノートパソコンの場合は、**ふたを閉じても止まらない**設定にします。
  管理者のターミナルで、次の5行を1行ずつ入力します。
  ```
  powercfg /change standby-timeout-ac 0
  powercfg /change standby-timeout-dc 0
  powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
  powercfg /setdcvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
  powercfg /setactive SCHEME_CURRENT
  ```
- **打刻用タブレット(iPad)側も**:「設定」→「画面表示と明るさ」→「自動ロック」を「なし」に。充電器につないだままにします。
- スリープから戻ったあとは、サーバーのパソコンの住所が変わることがあります。QRが出ないときは、`ipconfig` で住所を確認し、`.env` の `BASE_URL` と同じか確認してください。

## 2. システムを入れる

1. 配布された `server` フォルダを、サーバーのパソコンの `C:\kintai` にコピーします(`C:\kintai\src` などが見える状態)。
2. `C:\kintai\windows\1_初期設定.bat` をダブルクリックします。
   - 黒い画面が出て、設定ファイル(`.env`)が自動で作られます。
   - **メモ帳が開いたら**、`BASE_URL=http://192.168.1.10:3000` の `192.168.1.10` の部分を、手順1-2でメモした住所に書き換えて、保存して閉じます。
   - 続いて **最初の管理者** を作ります。「社員コード(半角英数字)」「氏名」「初期パスワード」を入力します。
3. `C:\kintai\windows\2_自動起動の登録.bat` を **右クリック →「管理者として実行」** します。
   - これで「パソコンを起動すると、自動でシステムが動く」ようになります。
   - あわせて、「社内ネットワークの機器からだけ接続できる」ようにファイアウォールが設定されます。
4. サーバーのパソコンのブラウザで `http://localhost:3000/admin` を開き、手順2で作った管理者でログインできれば完了です。
   - 初回は、パスワードの変更を求められます。

> **重要**:`.env` ファイルは「合鍵」のようなものです。他の人に渡さない、メールで送らない、というルールにしてください。

## 3. 最初の設定(管理画面)

管理画面は `http://サーバーの住所:3000/admin` です(例:`http://192.168.1.10:3000/admin`)。

### 3-1. 管理者を追加する(3人)
「社員」タブ →「＋社員を追加」 →「権限」を **管理者** にして保存します。
画面に **仮パスワード** が表示されます。**この画面を閉じると二度と見られません**。本人にだけ伝えてください。本人は最初のログイン時に自分でパスワードを変更します。

### 3-2. 社員を登録する
「社員」タブ →「＋社員を追加」

| 項目 | 内容 |
|---|---|
| 社員コード | 半角英数字(例:`E001`)。ログインに使います |
| 氏名 | 「山田 太郎」のように、**姓と名の間に半角スペース1つ**で統一します(表記ゆれ防止) |
| 勤務区分 | 正社員 / パート |
| 勤務体系 | 正社員のみ。パターン1(月金09:00 / 火木土09:20)かパターン2(月金09:20 / 火木土09:00) |
| パートの所定時間 | パートのみ。開始・終了・休憩の初期値(日ごとの申請で変えられます) |

### 3-3. 打刻用タブレットを登録する
1. 管理画面「タブレット」タブ → 名前(例:受付タブレット)を入れて「**登録用アドレスを発行**」を押します。
2. 表示されたアドレスを、**打刻用タブレットのブラウザ**で開きます(**15分以内・1回だけ有効**)。
3. QRコードの画面が出れば登録完了です。この画面をタブレットの常時表示にします。
   - 画面を **ホーム画面に追加**したり、ブラウザの全画面表示にすると、見やすくなります。
   - タブレットの「自動スリープ」は **しない** に設定してください。
4. **登録していない端末では、QR画面は開けません。** 紛失・交換のときは、「タブレット」タブで「**解除**」を押します(そのタブレットのQRは使えなくなります)。

## 4. 毎日の使い方

### 4-1. 社員(スマホ)
**打刻**
1. 出勤・退勤のとき、タブレットのQRコードを、スマホの **標準カメラ** で読み取ります。
2. 開いたページで、**初回だけ** 社員コードとパスワードを入力します(その後は、ログインしたままです)。
3. 「**出勤**」または「**退勤**」を押します。
   - 「もう一度QRコードを読み取ってください」と出たら、QRコードを読み取り直します(QRは30秒ごとに変わり、60秒で無効になります)。
   - 出勤前の退勤や、出勤済みでの再出勤のときは、確認が出ます。間違いでなければ「このまま打刻する」を押します。
   - 時刻は、サーバーの時刻で記録されます(スマホの時計がずれていても影響しません)。

**残業の申請**
1. 画面下の「**勤怠・申請**」→「＋残業を申請する」(または日付のカードの「残業を申請」)。
2. 日付と勤務区分(通常出勤 / 半日出勤 / 休日出勤)を選び、残業した時間帯を入力します(最大4枠、23:59まで)。
   - 定時の時間内に入っていると、赤い警告が出ます。
   - **日またぎの残業(0時を過ぎる)は入力できません。**
   - パートの方は、所定時間・休憩・残業の分数と理由を入力します。
3. 「申請する」を押すと、**承認待ち** になります。管理者が承認すると集計に入ります。「差し戻し」されたら、理由を確認して直し、もう一度申請します。
4. 申請できるのは、**31日前から7日先まで**です。承認済みの申請は、本人は直せません(管理者に依頼)。

**⚠ 警告が出たら**
打刻と申請が1分でも食い違うと、一覧に黄色い警告が出ます。例:
- 「残業申請の終了 20:00 が、退勤打刻 19:58 より後です」→ 実際より長く申請していないか確認。
- 「定時 18:30 より後の打刻があるのに、残業申請がありません」→ 残業の申請を忘れていないか確認。

### 4-2. 管理者
管理画面の各タブでできることです。

| タブ | できること |
|---|---|
| 日別 | その日の全員の出勤・退勤・残業申請・警告。打刻の修正、残業の代理入力 |
| 月別(締め期間) | 16日〜翌月15日の集計。社員名を押すと日ごとの詳細。**Excel出力** |
| 残業の承認 | 承認待ちの申請を「承認」「差し戻し」。差し戻しは理由が必要。**自分自身の申請は承認できません** |
| 打刻漏れ | 出勤だけ・退勤だけの日の一覧。そこから打刻を修正 |
| 社員 | 登録・編集・無効化・パスワード再設定 |
| タブレット | 登録・再登録・解除 |
| 修正履歴 | 誰が・いつ・何を・なぜ修正したか(削除できません) |
| データ | 旧データの取り込み、バックアップ |

**打刻や残業を直すとき**
- 必ず「**理由**」を入力します。
- **元の記録は消えません。** 無効扱いになり、新しい記録が追加され、「修正履歴」に残ります。

**Excel出力**(月別タブ)
- 「正社員」「パート」の2シートで、月間集計つき、A4横の印刷設定です。**出勤・退勤の打刻の列**が追加されています。
- **承認済みの申請だけ**が出力されます。出力の前に、承認待ちが残っていないか確認してください。

### 4-3. 休日出勤で深夜(22時〜5時)に入る場合
休日出勤に深夜の残業が含まれると、申請時と管理者の一覧に、「**休日出勤に深夜の残業が含まれています**」という警告が出ます。現時点では該当者がいない想定のため、**警告の表示だけ**で、計算は既存の方式のままです(休日の8時間内・8時間超と、深夜残業の両方に数えられます)。

## 5. 起動と停止

通常は **何もしなくて構いません**(パソコンを起動すると自動で動きます)。

| やりたいこと | 操作 |
|---|---|
| 動いているか確認 | `C:\kintai\windows\5_状態確認.bat` をダブルクリック |
| 止める | `4_停止.bat` を右クリック →「管理者として実行」 |
| 起動する | `3_起動.bat` を右クリック →「管理者として実行」 |
| パソコンを再起動する | 再起動すれば自動で起動します(1分ほどかかります) |

> **サーバーのパソコンの電源は、勤務時間中は切らないでください。** スリープもしない設定にしてあります。

## 6. バックアップと復元

### 6-1. 自動バックアップ
- **毎日 02:00** に、自動でバックアップが作られます(その時間にパソコンが止まっていたら、次に起動したときに作られます)。
- 保存先:`C:\kintai\backups`、ファイル名:`kintai-年月日-時分秒.db`
- **30日分** を残し、古いものは自動で削除されます。
- 保存先や日数、時刻は `C:\kintai\.env` の `BACKUP_DIR`(保存先)、`BACKUP_KEEP_DAYS`(日数)、`BACKUP_TIME`(時刻)で変えられます。変更したらサーバーを再起動します。
- **おすすめ**:サーバーのパソコンが壊れても大丈夫なよう、`backups` フォルダを **別の場所(外付けHDD、NAS、USBなど)に、週1回コピー**してください。`BACKUP_DIR` に外付けHDDのドライブ(例:`E:\kintai-backup`)を指定すれば、自動でそこに保存されます。
- **`.env` ファイルも別に保管**してください(バックアップには含まれません)。ただし他人が見られない場所に。

### 6-2. いますぐバックアップ
- 管理画面「データ」タブの「いますぐバックアップ」、または `windows\バックアップを今すぐ取る.bat` をダブルクリック。
- 大きな作業(旧データの取り込みなど)の前に実行しておくと安心です。

### 6-3. 復元(元に戻す)
データを間違えて壊してしまったときや、パソコンを入れ替えたときの手順です。

1. 戻したい日付の `backups\kintai-….db` を決めます。
2. `windows\バックアップから復元.bat` を **右クリック →「管理者として実行」** します。
3. 一覧からファイル名を入力し、`yes` と入力します。
4. 自動で、①サーバー停止 → ②現在のデータを `data\before-restore-…db` に退避 → ③復元 → ④サーバー再起動、が行われます。

**パソコンを入れ替える場合**:新しいパソコンで「2.システムを入れる」まで行い、`.env` を元のものに置き換え、`data\kintai.db` の代わりにバックアップを復元します。

## 7. よくある操作

| やりたいこと | 方法 |
|---|---|
| 社員が増えた | 「社員」タブ →「＋社員を追加」→ 仮パスワードを本人に伝える |
| 社員が退職した | 「社員」→「編集」→「有効」のチェックを外す(**削除はしません**。過去の記録は残ります) |
| パスワードを忘れた | 「社員」→「編集」→「パスワードを再設定」→ 表示された仮パスワードを本人に伝える |
| ログインがロックされた | 5回続けて間違えると15分ロックされます。15分待つか、管理者が「パスワードを再設定」します |
| 勤務体系を変えたい | 「社員」→「編集」で変更 |
| スマホを機種変更した | もう一度、社員コードとパスワードでログインするだけです |

## 8. 旧データ(旧HTML版)の取り込み

1. 旧HTML版(残業管理システム)を開き、「**集計・出力**」の画面にある「**バックアップを保存**」で、データをファイルに保存します(`勤怠残業バックアップ_….json`)。
   - ※ このボタンがあるのは、GitHubに置いてある新しい版の `index.html` です。ボタンがない古い版を使っている場合は、先に新しい版に切り替えてから保存してください(データは同じ「overtime_records」なので、そのまま引き継がれます)。
2. 管理画面「データ」タブで、そのファイルを選び「内容を確認する」を押します。
3. 旧データの名前ごとに、**社員マスタの誰にあたるか** を選びます(名前が同じなら自動で選ばれます。空白の違いは無視されます)。
4. 「取り込みを実行」を押します。
   - 取り込んだ分は **承認済み** になります。
   - 同じ社員・同じ日のデータがすでにある場合は、取り込まれません。
   - 日またぎの残業など、新しいルールで入力できない古いデータは、取り込まれずに一覧に表示されます。

## 9. トラブル対処

| 症状 | 確認すること・対処 |
|---|---|
| スマホでQRを読んだら「ページが開けません」 | ①スマホが **会社のWi-Fi** につながっているか(モバイル通信になっていないか)。②「Wi-Fiはつながっているがインターネットなし」と表示されて、スマホが自動でモバイル通信に切り替えていないか(スマホの設定で、このWi-Fiの「自動切り替え」「モバイルデータの優先」をオフ)。③サーバーのパソコンが起動しているか(`5_状態確認.bat`)。④ゲストWi-Fi・端末間通信の禁止がオフか |
| 「もう一度QRコードを読み取ってください」 | QRの有効期限切れです。読み取り直してください。何度もなる場合は、タブレットの時計・通信を確認してください |
| タブレットに「登録されていません」 | 管理画面「タブレット」で「再登録」し、表示されたアドレスをタブレットで開きます |
| タブレットのQRが更新されない | タブレットがWi-Fiにつながっているか確認。ブラウザを再読み込みしてください |
| 管理画面にログインできない | 社員コードとパスワードを確認。ロックされている場合は15分待つ。管理者が全員入れない場合は、サーバーのパソコンで `C:\kintai` を開き、`node scripts\create-admin.js 新コード 氏名` で新しい管理者を作ります |
| 全体が動かない | `5_状態確認.bat` を実行。応答がなければ `3_起動.bat`。それでもだめなら、パソコンを再起動。ログは `C:\kintai\logs\server.log` にあるので、困ったときは担当者に見せてください |
| 打刻時刻がおかしい | サーバーのパソコンの時計がずれている可能性があります。Windowsの設定 → 時刻と言語 → 日付と時刻 で「今すぐ同期」。タイムゾーンは(UTC+9)大阪、札幌、東京 |
| データが消えた・壊れた | 「6-3 復元」を行います |
| 打刻を忘れた | 管理画面「打刻漏れ」または「日別」から、理由をつけて打刻を修正します |

## 10. 設定ファイル `.env` の項目

メモ帳で開いて編集します。変更したら、`4_停止.bat` → `3_起動.bat` で再起動します。

| 項目 | 意味 | 初期値 |
|---|---|---|
| `PORT` | ポート番号 | 3000 |
| `BASE_URL` | QRコードに入るサーバーの住所(**必ず正しく**) | http://192.168.1.10:3000 |
| `TOKEN_SECRET` / `SESSION_SECRET` | 署名用の秘密鍵(**変更しない・他人に見せない**。変えると、QRとログインが全員やり直しになります) | 自動生成 |
| `QR_ROTATE_SECONDS` | QRを切り替える秒数 | 30 |
| `QR_TTL_SECONDS` | QRの有効秒数 | 60 |
| `PUNCH_COOLDOWN_SECONDS` | 連続打刻を拒否する秒数 | 60 |
| `LOGIN_MAX_FAILS` / `LOGIN_LOCK_MINUTES` | ログイン失敗の上限回数 / ロック時間(分) | 5 / 15 |
| `BACKUP_DIR` / `BACKUP_TIME` / `BACKUP_KEEP_DAYS` | バックアップの保存先 / 時刻 / 残す日数 | `./backups` / 02:00 / 30 |
| `DB_PATH` | データファイルの場所 | `./data/kintai.db` |

## 11. 用語集

- **IPアドレス**:ネットワーク上の「住所」。
- **ブラウザ**:ChromeやSafariなど、ウェブページを見るアプリ。
- **締め期間**:16日〜翌月15日。給与計算の単位です。
- **仮パスワード**:管理者が発行する、最初だけ使うパスワード。
